# V1.2 Implementation Guide

## 新项目

1. 复制 `.codex/` 与 `scripts/`。
2. 初始化 `project.yaml / goals.yaml / requirements.yaml / tasks.yaml`。
3. 定义 `guardrails.yaml` 的允许/禁止范围。
4. 为当前 Task 创建 Alignment Review。
5. 从 READY 进入 IN_PROGRESS。
6. 开发、测试、记录 Evidence。
7. 运行 Health Check。
8. 通过后进入下一个 Task / Phase。

## 已开发一段时间的项目

先运行：

```bash
./scripts/project-audit.sh
```

不要直接继续写业务代码。先把：

- Mission
- Goals
- 当前 Release
- Requirement Baseline
- Task Tree
- Stable Baseline
- 已知 Bug
- 风险
- 未验证假设
- 现有版本差异

整理成当前真实状态，再恢复开发。

## 发现新需求

不要直接改 TASKS。

先建立 CR：

```text
DRAFT
↓
ANALYZED
↓
Impact Review
↓
APPROVED_CURRENT / APPROVED_FUTURE / BACKLOG / REJECTED
```

## 发现“之前设计可能错了”

不要覆盖旧决定。记录新的 Decision，并在需要时创建 CR；让旧结论仍然可以被追溯。

## 发现 Bug

按：

`现象 → 直接原因 → 根因 → 临时修复 → 永久修复 → 回归证据`

处理。

## 发布前

至少通过：

```bash
./scripts/project-health.sh
python3 scripts/check_release_trace.py
```

并确保 Git tag 与 `release.yaml` 对齐。
