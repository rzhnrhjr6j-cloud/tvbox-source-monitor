# Codex Project Control Framework V1.2 — Semantic Governance

V1.2 在 V1.1 状态机之上增加“语义治理层”。核心目的不是让机器假装拥有完整产品理解，而是让 Codex 的解释、修改和新增需求都必须落到可追溯的合同上。

## 1. 四层保护

1. 产品目标层：Mission / Goals / Non-negotiables
2. 需求合同层：Goals / Scope Tags / Non-goals / Acceptance Criteria
3. 执行层：Task / Allowed Paths / Dependencies / Alignment Review
4. 证据层：Tests / Evidence / Release Trace

## 2. Drift Guard

`check_drift.py` 会阻止常见的形式化漂移：

- 当前任务没有目标或需求锚点
- task scope tags 不在允许范围
- 出现显式禁止 scope tag / term
- task scope 与 non-goal 冲突
- 没有 Alignment Review
- requirement 缺乏 scope contract

它不会声称可以自动判断自然语言中的全部业务意图；对真正的语义边界，要求 Codex/人工提交 Alignment Review，并让机器检查 Review 是否存在、是否与当前任务状态一致。

## 3. Release Trace

Release 必须能追到：

`Goal → Requirement → Task → Evidence → Release`

任何链断，Release Trace Fail。
