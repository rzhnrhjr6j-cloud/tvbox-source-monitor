# 数据库结构

V1 用单个 SQLite 文件：`data/monitor.db`（路径由 `app.db_path` 配置）。

GitHub Actions 每轮把库下载下来、更新、再提交回去。库变大后的 V2 方案
（artifacts / 压缩历史 / 外部数据库）见规格 §24 / §34。

`SCHEMA_VERSION = 3`，迁移由 `app/storage/migrations.py` 负责，启动时自动跑。

## 表一览

| 表 | 作用 |
|:---|:---|
| `sources` | 每个源一行：身份、状态、分数、地区、计数器 |
| `probe_results` | 每次探测一行（保留 `app.probe_retention_days` 天） |
| `daily_stats` | 按源 × 地区 × 天聚合，可用率与稳定性都由它算 |
| `alerts` | 告警与去重指纹 |
| `discoveries` | 发现记录（含被拒的），用于冷却期判断 |
| `source_events` | 状态变更审计流水 |
| `build_history` | 每次构建的结果（规格 §31） |
| `nodes` | 探针节点健康 |
| `meta` | 键值：schema 版本、最近运行时间、上次发布等 |

---

## sources

主键 `id` = `sha256(规范化 URL)`，所以同一个源的 `http`/`https`、结尾斜杠、
GitHub blob/raw 等写法会归到同一行。

关键列：

| 列 | 说明 |
|:---|:---|
| `url` / `raw_url` | 规范化地址 / 首次见到的原始写法（抓取用后者） |
| `type` | `single` / `multi`（多仓包装） |
| `parent_id` | 多仓展开出来的子源指向父源（lineage） |
| `schema` | 探测到的配置形状：`single` / `sites` / `multi` |
| `status` | 生命周期状态，见下 |
| `tier` | 输出分层：`primary` / `backup` / `experimental` / `none` |
| `score` | 综合分（0–100） |
| `stability_score` | 历史稳定性（30d/7d/近期加权） |
| `search_score` / `playback_score` / `latency_score` / `regional_score` / `freshness_score` / `availability_score` | 各分量，方便排查 |
| `candidate_score` | 准入分（规格 §27） |
| `consecutive_success` / `consecutive_failure` | 连击计数，驱动生命周期楼梯 |
| `max_consecutive_*` | 历史极值 |
| `total_checks` / `total_successes` / `total_failures` | 累计 |
| `global_status` | 多地区仲裁：`GLOBAL` / `REGIONAL` / `FAILED` / `UNKNOWN` |
| `regions_ok` / `regions_failed` | JSON 数组 |
| `node_count` | 本轮报告的节点数 |
| `last_success_at` / `last_failure_at` / `last_recovery_at` / `last_outage_at` | 时间线 |
| `whitelisted` / `blacklisted` / `paused` | 人工干预与自动暂停 |

`status` 取值：`discovered` / `candidate` / `validating` / `active` / `degraded` /
`failed` / `recovering` / `blacklisted` / `rejected`。

`paused` 的含义是**不输出**，不是**不检测**——被暂停的源仍会被探测，否则永远无法恢复。

索引：`status`、`parent_id`、`score DESC`。

---

## probe_results

每次探测一行，`error_stage` 指出是哪一层出的问题，便于日志定位
（规格 §35-13）：

| error_stage | 层 |
|:---|:---|
| `L1_http` | 连通性 |
| `L2_config` | 配置解析 |
| `L3_search` | 搜索接口 |
| `L4_detail` | 详情接口 |
| `L5_playback` | 播放地址探针 |

布尔列以 0/1 存储：`http_ok`、`dns_ok`、`tls_ok`、`config_parse_success`、
`search_success`、`detail_success`、`detail_has_playlist`、
`playback_url_obtained`、`playback_probe_success`。

索引：`(source_id, ts)`、`(region, ts)`。

---

## daily_stats

按 `(source_id, region, day)` 聚合。可用率（`availability`）和稳定性窗口
全部由这张表推导——它是 `probe_results` 的物化视图，避免每次评分都扫原始表。

索引：`day`。

---

## alerts

| 列 | 说明 |
|:---|:---|
| `kind` | `source_failed` / `source_recovered` / `score_drop` / `build_blocked` / `node_down` / `output_rollback` |
| `severity` | `info` / `warning` / `critical` |
| `fingerprint` | 去重指纹；`suppress_window_hours` 内同指纹不再发 |
| `resolved_at` | 非 NULL 表示已恢复/已解决 |
| `channels` | 已投递的通道（JSON 数组） |

索引：`(fingerprint, created_at)`、`(resolved_at, created_at)`。

---

## discoveries

记录每条被发现的 URL（**包括被拒的**），`admitted` 为 0/1，`reason` 写拒绝原因。
准入冷却期（`admission.reject_cooldown_hours`）靠它判断，避免反复重试同一个坏地址。

索引：`(normalized_url, found_at)`。

---

## source_events

审计流水：`discovered` / `admitted` / `rejected` / `checked` / `status_change` /
`score_change` / `recovered` / `failed` / `removed` / `restored` / `blacklisted` /
`whitelisted`。带 `from_status` / `to_status`。

索引：`(source_id, ts)`。

---

## build_history（规格 §31）

每次构建一行：

`build_id` / `generated_at` / `git_sha` / `active_count` / `degraded_count` /
`failed_count` / `new_count` / `recovered_count` / `removed_count` /
`source_count` / `published` / `fallback` / `blocked_reason` / `output_sha256` /
`primary_count` / `backup_count` / `experimental_count`

`fallback = 1` 表示这次是回滚（用了 last-known-good）。
`blocked_reason` 非空表示被安全阀拦下。

索引：`generated_at DESC`。

---

## nodes

探针节点：`name`（主键）/ `region` / `url` / `enabled` / `weight` /
`last_seen_at` / `last_ok_at` / `consecutive_failures` / `note`。

---

## meta

键值表，重要的键：

| key | 说明 |
|:---|:---|
| `schema_version` | 迁移用 |
| `last_run_at` | 最近一轮结束时间 |
| `published_source_ids` | 上一次真正发布出去的源 id 列表（JSON） |
| `last_good_build_id` | 最近一次成功发布的构建号 |

---

## 常用查询

```sql
-- 现在有多少源、各状态几个
SELECT status, COUNT(*) FROM sources GROUP BY status ORDER BY 2 DESC;

-- 分数最高的 20 个
SELECT name, score, stability_score, status, tier
FROM sources ORDER BY score DESC LIMIT 20;

-- 最近 24h 成功率
SELECT region, COUNT(*) AS checks,
       ROUND(100.0 * SUM(http_ok AND config_parse_success) / COUNT(*), 2) AS ok_pct
FROM probe_results
WHERE ts >= datetime('now', '-1 day')
GROUP BY region;

-- 最近 10 次构建
SELECT build_id, generated_at, published, source_count, blocked_reason
FROM build_history ORDER BY generated_at DESC LIMIT 10;

-- 还没解决的告警
SELECT kind, source_id, region, title, created_at
FROM alerts WHERE resolved_at IS NULL ORDER BY created_at DESC;

-- 某个源为什么掉分
SELECT search_score, playback_score, latency_score, stability_score,
       availability_score, regional_score, freshness_score
FROM sources WHERE name = 'Source-A';
```
