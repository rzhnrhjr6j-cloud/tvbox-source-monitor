# 部署指南

目标：影视仓里填一次 `https://<用户名>.github.io/<仓库名>/tvbox.json`，之后不再手动维护。

---

## 0. 前置条件

- 一个 GitHub 账号
- 本机有 `git`
- 想用一键脚本的话，还需要 `gh`（GitHub CLI）并已登录

检查：

```bash
git --version
gh --version
gh auth status
```

`gh auth status` 里必须包含 `repo` 和 **`workflow`** 两个 scope。
没有 `workflow` 就无法推送 `.github/workflows/*`：

```bash
gh auth refresh -s workflow
```

（会打开浏览器让你确认一次。）

---

## 1. 一键部署

```bash
cd tvbox-source-monitor
./deploy.sh --repo tvbox-source-monitor --public
```

脚本按顺序做这些事：

1. 检查 `git` / `gh` 与登录状态、`workflow` scope
2. 生成 `.env`（如果不存在）并确认 `.gitignore` 忽略它
3. `git init` + 首次提交
4. `gh repo create` 建仓库并推送
5. 设置 Secrets：`GH_TOKEN`、`ALERT_GITHUB_REPO`
6. 提示你去开 Pages（Source = **GitHub Actions**）
7. 触发一次 `nightly-build` 和 `pages`

私有仓库也可以，但 **GitHub Pages 在免费账号下要求仓库公开**，
否则 Pages 会 404。想省事就用 `--public`。

部署完，影视仓里的地址是：

```text
https://<你的用户名>.github.io/<仓库名>/tvbox.json
```

## 2. 手工部署（不用脚本）

```bash
cd tvbox-source-monitor

git init -b main
git add -A
git commit -m "feat: tvbox-source-monitor V1.0"

# 建仓库并推送（把 <user> 换成你的用户名）
gh repo create <user>/tvbox-source-monitor --public --source=. --remote=origin --push
```

如果不想用 `gh`：先在网页上建一个空仓库，然后

```bash
git remote add origin https://github.com/<user>/tvbox-source-monitor.git
git push -u origin main
```

### 2.1 设置 Secrets

仓库 → Settings → Secrets and variables → Actions → New repository secret：

| 名称 | 必填 | 用途 |
|:---|:---|:---|
| `GH_TOKEN` | 建议 | 发现适配器用。一个 fine-grained PAT，勾选 **Public Repositories (read-only)** 即可 |
| `ALERT_WEBHOOK_URL` | 可选 | 通用 JSON webhook（Slack / 飞书 / 钉钉 / Discord 中转） |
| `TELEGRAM_BOT_TOKEN` | 可选 | Telegram 告警 |
| `TELEGRAM_CHAT_ID` | 可选 | Telegram 告警 |

`GITHUB_TOKEN` 不用手动设置，Actions 会自动注入。

不配 `GH_TOKEN` 也能跑，只是 GitHub 代码搜索适配器会被跳过（日志里会有
`github adapter disabled: no GH_TOKEN/GITHUB_TOKEN in the environment`）。

### 2.2 开启 Pages

仓库 → Settings → Pages → **Build and deployment → Source = `GitHub Actions`**。

⚠️ 必须是 `GitHub Actions`，不要选 `Deploy from a branch`——`dist/` 不在分支根目录。

### 2.3 首次运行

Actions → `nightly-build` → Run workflow。

跑完检查：

```bash
curl -sI https://<user>.github.io/<repo>/tvbox.json | head -1
curl -s  https://<user>.github.io/<repo>/tvbox.json
```

第一次很可能只看到 `{}` 或没有文件——这是**正常的**，因为候选池还是空的。
见下一节。

## 3. 让它有源可用

系统不会凭空猜到你该用哪些源。三选一：

### A. 手工加（最直接）

编辑 `data/candidates.json`：

```json
{
  "urls": [
    "https://example.com/authorized/config.json",
    { "url": "https://example.com/multi.json", "name": "多仓示例", "tags": ["手动"] }
  ]
}
```

只放**公开可访问、你有权使用**的地址。commit 之后 discover 会自己准入。
多仓地址会自动拆出子源。

### B. 靠 GitHub 搜索适配器

配好 `GH_TOKEN` 后，`make discover` / `discover.yml` 会按
`config/discovery.yaml` 里的 `code_queries` 找 `tvbox.json`。
搜索词可以自己改。

### C. 白名单兜底

把不想被淘汰的源写进 `data/whitelist.json`，它会跳过淘汰判定。

### 首次通过安全阀

安全阀要求至少 `output.min_sources`（默认 **3**）条源才允许发布。
所以初次部署后源少于 3 条时，`dist/tvbox.json` 不会被写出来——这是设计如此，
不是故障。凑够 3 条就会发布；想先看效果可以把 `config/app.yaml` 里的
`output.min_sources` 临时改成 `1`。

## 4. 调度

四个 workflow（全部 UTC，`config` 之外的调度在 YAML 里）：

| workflow | 触发 | 做什么 |
|:---|:---|:---|
| `discover.yml` | 每 6 小时 `7 */6 * * *` | 发现新候选 → 更新 `data/` |
| `health-check.yml` | 每 30 分钟 `13,43 * * * *` | 检测现有源 → 写 `data/` |
| `nightly-build.yml` | 每天 20:00 UTC（= 04:00 北京时间） | 重新评分 → 淘汰 → 恢复 → 生成 → 校验 → 提交 `data/` + `dist/` |
| `pages.yml` | 上游跑完 / 手动 / push 到 `dist` `dashboard` | 发布 Pages |

**为什么要用 `workflow_run` 而不是纯 `push`**：用仓库自带的 `GITHUB_TOKEN`
推的提交**不会触发其它 workflow**（GitHub 的既定行为）。所以 nightly 提交完
`dist/` 之后，纯 `push` 触发器的 `pages.yml` 永远不会跑。`workflow_run` 不受这个限制。

三个写仓库的 workflow 共用一个 `concurrency: tvbox-data-write` 组，
避免同时提交 SQLite 数据库导致推不上去。推之前会 rebase，失败最多重试 3 次。

## 5. 部署后自检

```bash
# 1. 工作流状态
gh run list --limit 10

# 2. 最新一次 build 的日志
gh run view --log --job $(gh run list --workflow=nightly-build --limit 1 --json databaseId -q '.[0].databaseId')

# 3. Pages 是否发布成功
curl -s https://<user>.github.io/<repo>/dashboard.json | head -40

# 4. 面板
open https://<user>.github.io/<repo>/dashboard/
```

## 6. 常见部署失败

| 现象 | 原因 / 解决 |
|:---|:---|
| `refusing to allow a Personal Access Token to create or update workflow` | `gh` 缺 `workflow` scope → `gh auth refresh -s workflow` |
| `pages.yml` 一直不触发 | Pages Source 没设成 `GitHub Actions`；或仓库私有 |
| `tvbox.json` 404 | 还没发布过（源不足 `min_sources`），或 Pages 未开 |
| `tvbox.json` 是 `{}` | 同上，候选池为空 |
| workflow 报 `could not push after 3 attempts` | 两个写库 workflow 撞车；重跑即可，`concurrency` 组已尽量减少这种情况 |
| `fatal: pathspec 'dist' did not match any files` | 已修：脚本里加了 `[ -d dist ]` 判断 |

更多见 `docs/故障排查.md`。
