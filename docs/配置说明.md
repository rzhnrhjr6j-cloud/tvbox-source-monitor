# 配置说明

所有阈值都在 `config/*.yaml`，代码里不硬编码（规格 §35-14）。
字符串里可以写 `${VAR}` 或 `${VAR:-默认值}`，加载时展开——所以同一份 YAML
在本地、`.env` 和 GitHub Secrets 里都能用。

> ⚠️ 环境变量是**加载后**做的文本替换，所以布尔值写成 `${VAR:-false}`
> 时得到的可能是字符串 `"false"`。布尔开关建议直接写 YAML 的 `true` / `false`。

#### format 的三种形状

`multi`（默认）：

```json
{ "version": "1.0", "generated_at": "...", "urls": [{"name": "A", "url": "https://..."}] }
```

`sites`：

```json
{ "sites": [{"key": "A", "name": "A", "type": 3, "api": "https://...", "searchable": 1, "quickSearch": 1, "filterable": 1}] }
```

`single`：`sites[]` 与 `sites` 相同，另外补上空的 `lives: []` 和 `parses: []`
（影视仓单仓配置通常要求这两个键存在）。

#### template 精确覆盖

规格 §18 要求用真实影视仓 6.1.8 核对字段布局。如果你那边的形状不在上面三种里，
**不要改代码**，写 `output.template` 即可。列表里放一个带 `"$each"` 键的对象作为
逐条模板；可用的占位符：

| 占位符 | 含义 |
|:---|:---|
| `$name` | 显示名 |
| `$url` / `$api` | 抓取地址 |
| `$id` / `$key` | 源 id（`$key` 是前 16 位） |
| `$score` / `$tier` / `$status` / `$type` | 当前分数 / 分层 / 状态 / 类型 |
| `$generated_at` / `$version` / `$count` | 顶层标量 |

例子：

```yaml
output:
  template:
    version: "1.0"
    generated_at: "$generated_at"
    count: "$count"
    sites:
      - $each: true
        name: "$name"
        api: "$url"
        type: 3
```

#### mirror 镜像（规格 §18 / §37）

```yaml
output:
  mirror:
    enabled: true
    public_base: ""        # 空 = 用 GITHUB_REPOSITORY 推成 https://<owner>.github.io/<repo>
    on_failure: drop       # drop = 镜像不了就不发布；keep = 退回原始地址
    max_bytes: 2097152     # 单个配置文件上限
    max_total_bytes: 33554432
    rewrite_inner: true    # 配置内部指向 raw.githubusercontent.com 的链接套加速前缀
    inner_proxy: "https://gh-proxy.com/"   # 加速前缀，可换 ghfast.top / ghproxy.net
```

**为什么默认开**：发现的源基本都在 `raw.githubusercontent.com`，国内直连不通，
而检测跑在海外机器上测不出来。开启后构建会把配置内容抄一份到
`dist/sources/<source_id 前 16 位>.json`，并把 `tvbox.json` 里的地址改写成
`<public_base>/sources/<...>.json`。影视仓只访问你自己的 `github.io`。

**内层引用**：镜像只解决「`tvbox.json` 指向谁」这一步。配置内部还有一层指针——
`urls[]` 里的同级配置、`lives[]` 里的直播列表、`sites[]` 里少数走 GitHub 的脚本。
实测 24 份配置里共 86 处这样的引用，全在 `raw.githubusercontent.com`。只镜像外层，
这些内层引用在国内依然是死的（配置能读进来，里面的子源全打不开），所以默认给它们
套上 `inner_proxy`，写成 `https://gh-proxy.com/https://raw.githubusercontent.com/...`。
已经带前缀的引用不会被套第二次。

| 选项 | 说明 |
|:---|:---|
| `enabled` | 总开关。`false` 时行为跟以前一样，直连原始地址 |
| `public_base` | 发布地址前缀。留空则从 `GITHUB_REPOSITORY` 推导；两者都取不到就**自动跳过镜像**（本地跑就是这样，所以本地不受影响）|
| `on_failure` | 抓不到配置时怎么办。`drop` 更诚实——发一个国内打不开的地址没意义；`keep` 保守，退回原地址 |
| `max_bytes` / `max_total_bytes` | 防呆上限，超了就跳过（并记日志）|
| `rewrite_inner` / `inner_proxy` | 上面的内层引用改写。`rewrite_inner: false` 原样发布（对照/调试用）；`inner_proxy` 是套在裸链接前面的加速前缀 |

## config/scoring.yaml

| 段 | 说明 |
|:---|:---|
| `weights` | 七个评分分量，**必须合计 1.0**，否则启动即报错 |
| `status_thresholds` | `active` 70 / `degraded` 50：`>= active` ⇒ ACTIVE，`>= degraded` ⇒ DEGRADED，否则 FAILED |
| `stability.windows` | 30 天 50% + 7 天 30% + 近期 20%；没有数据的窗口会被丢掉并重新归一化，新源不会因为「没历史」被罚 |
| `decay.half_life_days` | 新鲜度半衰期，14 天 |
| `latency.buckets` | 平均响应时间 → 分数 |
| `lifecycle` | 见下表 |
| `candidate.threshold` | 准入分数线，55 |
| `candidate.weights` | 可达性 / JSON / schema / https / 多仓引用 / 初次搜索 |
| `discovery_cache_hours` | 发现结果缓存时长 |

`lifecycle` 就是规格 §11 的楼梯：

| 键 | 默认 | 含义 |
|:---|:---|:---|
| `fail_1_keep` | true | 单次失败不惩罚 |
| `fail_downgrade` | 2 | 2–3 次失败开始掉分 |
| `fail_pause_output` | 5 | 5 次失败 ⇒ 暂停输出（DEGRADED，不再进产物） |
| `fail_mark_failed` | 12 | 12 次失败 ⇒ FAILED |
| `recover_min_success` | 3 | 3 次连续成功 ⇒ RECOVERING |
| `recover_to_active` | 5 | 5 次连续成功 ⇒ ACTIVE |

> 两条重要语义：
> 1. **暂停输出 ≠ 停止探测**。暂停的源仍会被检测，否则它永远不可能恢复。
> 2. 爬完楼梯拿到 ACTIVE 后，只要连续成功不被打断、且分数不低于 `degraded` 线，
>    就不会被落后的 7 日均值打回 DEGRADED（否则每轮都会抖）。

## config/discovery.yaml

| 段 | 说明 |
|:---|:---|
| `enabled_adapters` | `manual` / `github` / `expansion`，需要网页抓取再加 `web` |
| `github.code_queries` / `repo_queries` | 搜索词，可自行增删 |
| `github.per_page` / `max_pages` | 分页上限 |
| `github.min_rate_limit_remaining` | 剩余配额低于此值就停止翻页 |
| `github.path_patterns` / `path_excludes` | 哪些路径算候选 / 哪些明确不是 |
| `expansion.max_depth` / `max_children` | 多仓递归深度与子源上限 |
| `manual.file` | 候选池文件名（实际读取 `<data_dir>/candidates.json`） |
| `admission.*` | 准入规则：是否要求 https、是否要求 JSON content-type、最大体积、拒绝 HTML/二进制、拒绝冷却期、是否做初次搜索、单轮最多抓多少 |
| `dedup.*` | 去重规则：是否去掉追踪参数、追踪参数名单、host 大小写 |

> `dedup` 只删**名单里的**追踪参数（`utm_*` / `spm` / `from` / `ref` 等），
> **不会**删除未知查询参数——`?token=` 这类参数是源正常工作所必需的，
> 删掉既会让源失效，也会把两个不同的源错误地合并成一个。

## config/regions.yaml

| 键 | 说明 |
|:---|:---|
| `local.enabled` / `region` / `node_name` / `weight` | GitHub runner 自己充当一个地区。自托管 runner 改 `region` 即可 |

| `enabled_regions` | 期望参与的地区列表 |
| `quorum.global_success_ratio` | 成功地区占比 ≥ 此值 ⇒ GLOBAL |
| `quorum.min_nodes_for_quorum` | 少于这么多节点报告 ⇒ 判定为 UNKNOWN（不惩罚，给中性分） |
| `quorum.region_success_ratio` | 某地区内成功节点占比 ≥ 此值 ⇒ 该地区算「通」 |
| `node_failure_tolerance` | 节点不可达的容忍数量 |
